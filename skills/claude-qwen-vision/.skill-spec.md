## 设计要点（Phase 0 记录 + 实现期修订）

- **动机**：DeepSeek 驱动的 Claude Code 收不到/读不懂图片内容块。本 skill 让主模型在遇到图时，
  主动调 qwen3.8-max（Anthropic 兼容端点）把图转成文本，再用文本继续推理。
- **两种图片来源都要支持**：
  a) prompt 里带图片文件路径 → 脚本直接收路径；
  b) 粘贴进终端的图 → `user_prompt_hook.py`（UserPromptSubmit hook）自动处理。
- **模型视觉能力判定（check_vision.py）**：Anthropic 兼容端点不暴露能力标志 → 经验探测 +
  **环境变量快速路径**（用户建议）：base/model 命中 deepseek（且非 deepseek-vl）→ 直接判盲；
  命中 claude/gpt-4o/gemini/qwen-vl 等 → 直接判有视觉；未知才探测一次并缓存。
  注意：qwen 家族**不能**用名字判断（qwen3.8-max 无 vl 却支持视觉；本地 omlx 部署会静默丢图）。
- **探测图必须 >10px**：qwen 端点硬限制（1x1 会 400 InvalidParameter）→ 用 32x32。
- **DeepSeek v4-flash 实测**：图片被静默替换为 `[Unsupported Image]`（不 400），turn 照常进行
  → hook 注入 additionalContext 可端到端工作。早期 V3 会 400（NO_VISION_HARD），hook 救不了。
- **hook 契约（官方文档验证）**：UserPromptSubmit stdin 只有 prompt 文本（无图片块）；
  粘贴图在 prompt 里是 `[Image #N]` 标记；字节在 `$CLAUDE_CONFIG_DIR/image-cache/<session_id>/N.ext`
  （未文档化，会随会话清理）或 transcript JSONL（文档化，异步写入需轮询 ≤4s）；
  `hookSpecificOutput.additionalContext` 注入为系统提醒（模型可见）；**不能替换 prompt**。
- **凭证**：绝不硬编码。运行时 `mytokens get qwen …` 取 ANTHROPIC_AUTH_TOKEN 等，内联消费。
- **CLAUDE_CONFIG_DIR** 指向别处（~/.csk）时，全局 skill 和 hook 都读不到，需分别装。

## 测试记录（Phase 3）

- **触发测试**：should_fire 3/3（带图 fixture 目录跑，路径类 case）· decoys 5/5 清（**空项目**跑）。
  - 方法论教训 1：blind 探测模型 + 满是图片的 fixture 目录会让 decoy 合理触发 claude-qwen-vision
    （Glob 找到图 → Read 读不出 → 找视觉 skill）——decoys 必须在无图项目里测。
  - 方法论教训 2：粘贴图的 case（「[Image #N]」）在文本探测里固有抖动（没有真图，模型行为随机），
    从触发测试移出——其真实覆盖在 hook 功能测试（确定性）。
  - 方法论教训 3：description 里不能放探测环境跑不了的指令（check_vision.py 要 Bash，探测时被禁用）
    → 模型会绕过去自己 Read。description 改为「直接用 qwen_vision.py，不要试图直接看图」后，
    Read-first 的抖动也消失（3/3 稳定）。
- **功能测试**：PIL 生成「HELLO 42」测试图 → `qwen_vision.py`（路径模式 + --base64 模式）
  输出均含 HELLO 42 ✓；`check_vision.py` DeepSeek→NO_VISION_SILENT（fast path） / qwen→VISION ✓；
  hook 三条路径（image-cache / transcript 兜底 / 无图 no-op）✓；install-hook.sh 合并+幂等 ✓。
- **改名记录**：`qwen38vision` → `claude-qwen-vision`（skill 名/目录/repo 全换），改名后全量重测通过。
